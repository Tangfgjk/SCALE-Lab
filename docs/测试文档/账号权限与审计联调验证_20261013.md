# 账号权限与审计联调验证

日期：2026-10-13。环境：本地 Docker PostgreSQL 17，`frontend/server/platform.js` 监听 `127.0.0.1:3001`。使用合成内容人员账号测试，测试后删除账号、凭据、会话及其账号操作记录；初始管理员不变。

## 实现

- `frontend/server/accounts.js`：管理员创建账号、修改显示名和角色、启停账号、重置密码；所有登录人员可修改本人密码。启用账号上限 5 个。停用与密码重置撤销旧会话，角色变更对已有会话立即生效。
- `frontend/server/auth.js`：补充管理员权限校验，沿用本地 `scrypt` 加盐密码哈希、12 小时可撤销会话和 CSRF 保护。保留 `admin_identities` 的 provider 字段，后续可接学校统一身份认证。
- `frontend/admin/`：管理员账号列表及创建、编辑、密码重置；内容人员只显示本人改密区。
- 操作记录：按操作人、动作、内容 ID、日期筛选最近 100 条；日期按 `Asia/Shanghai` 的自然日解释。账号变动写入审计，不记录明文密码。

## 验证结果

1. `npm run test:accounts` 通过：未登录 401；内容人员可以访问内容接口但管理账号为 403；管理员可创建账号；短密码拒绝；角色变更立即生效；本人改密、管理员重置及停用均使相应旧会话失效；可重新启用；管理员不能停用自己；审计筛选与错误日期校验通过。
2. `npm run test:research`、`npm run test:settings` 回归通过，确认新账号路由不截获其他模块。
3. 浏览器打开后台“账号管理”和“操作记录”：账号表单、列表、筛选和记录正常显示；控制台仅有浏览器此前请求默认 favicon 的 404，已在页面添加显式图标路径。
4. 九组自动化回归依次通过：新闻、中英文新闻、研究、中英文研究、成员、中英文成员、媒体相册、站点设置、账号；`git diff --check` 无空白错误。

## 未完成与后续

- 当前只有本地专用账号；学校统一身份认证入口、云端 HTTPS 与密码找回渠道待部署方案确定。
- 账号创建时由管理员设置初始密码并通过可信渠道交付；系统没有外发邀请邮件。当前本地初始密码由用户指定，未写入仓库，云端发布前必须替换。
- 操作记录当前按条件读取最近 100 条；如需长期审计导出、精确分页与保留策略，进入云端运维阶段设计。
