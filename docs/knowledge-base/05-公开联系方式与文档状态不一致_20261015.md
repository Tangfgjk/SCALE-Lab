#### 问题现象

站点设置的中文版正式发布记录明确显示联系邮箱为空，项目决策 D06 也说明官方联系邮箱和招生入口尚未确认；但公开文化页仍在 [frontend/visual-preview-20261013/culture.html](../../frontend/visual-preview-20261013/culture.html) 中硬编码 `zfwang@ccnu.edu.cn` 和 `404717268@qq.com`。另外，部分 2026-10-13 进度文档仍写“46 位成员”“照片待接入”，与 2026-10-14 阶段验收中已记录的 48 位成员和 3 位教师头像接入不一致。

#### 风险

1. 未确认邮箱可能被误认为正式公开联系渠道，产生隐私、授权和联系有效性风险。
2. 页面固定文案绕过站点设置发布流程，后台无法统一撤回或审计。
3. 旧文档数字和状态会误导后续开发、测试和验收判断。

#### 处理建议

1. 在代码修改阶段移除文化页硬编码邮箱，改为只读取已发布站点设置的 `contactEmail`；为空时隐藏联系方式区或显示待确认状态。
2. 在负责人确认邮箱、招生入口和文案来源后，通过后台设置发布，不在 HTML 中保留备用私人地址。
3. 保留 V2 历史文档的原始日期，但在文档顶部或相关结论处增加“以 2026-10-14 阶段验收和 V3 方案为最新状态”的交叉说明；不得回写历史验证结果。
4. V3 代码验收增加检查：公开 HTML、静态 JS、API 响应和页面截图中不得出现未确认联系方式；成员数量和头像状态以最新验收文档为准。

#### 验证出口

- 公开站中文、英文及无设置回退场景均不展示未确认邮箱。
- 后台站点设置为空邮箱时，公开页没有 `mailto:` 联系项。
- 联系邮箱通过后台发布后，公开页、API 和审计记录一致。
- 文档索引指向 V3 方案，最新进度不再使用 46 位成员和“照片未接入”作为当前状态。
