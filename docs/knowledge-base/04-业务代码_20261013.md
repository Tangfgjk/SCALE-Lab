### [ACCOUNTS-ROUTE-001] 账号权限中间件拦截了其他内容路由

#### 问题现象

新增账号接口后，内容人员请求 `/api/admin/v1/news` 返回 403；调整挂载位置后，管理员创建 `/api/admin/v1/users` 又返回 `NOT_FOUND`。账号管理本身能登录，但其他业务路由受影响。

#### 定位过程

1. `test:accounts` 首次运行在内容人员读取新闻时发现 403。
2. 检查 `accounts.js`：`admin.use(requireAdmin)` 应用于整个挂载路径，未匹配的内容请求也被拒绝。
3. 把账号 Router 放在研究 Router 后又出现 `NOT_FOUND`；研究 Router 的 `/:kind` 泛匹配先消费了 `/users`。

#### 根本原因

Express 按挂载顺序处理 Router。无路径限制的 `requireAdmin` 会检查所有进入 `/api/admin/v1` 的请求；泛参数路由 `/:kind` 也会覆盖后续模块的固定资源名。

#### 解决方案

在 `frontend/server/accounts.js` 将权限中间件限制为 `admin.use('/users', requireAdmin)`；在 `frontend/server/platform.js` 将账号 Router 放在固定资源 Router 之后、研究泛路由之前。普通内容接口仍由各自 Router 的 `requireUser` 守护，账号写接口再执行管理员与 CSRF 检查。

#### 验证方法

`npm run test:accounts`：内容人员读取新闻为 200、管理用户为 403；管理员创建用户为 201。`test:research`、`test:settings` 和九组完整回归均通过。
