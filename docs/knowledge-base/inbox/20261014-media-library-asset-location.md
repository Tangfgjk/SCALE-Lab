#### 问题现象

媒体库计划支持图片整理、重命名、库与文件夹层级。需要明确图片被新闻引用后移动、重命名、替换或停用时，新闻引用是否失效。

#### 定位过程

- 现有 `assets` 使用 UUID 和唯一 `storage_key` 标识文件，新闻富文本尚未接入媒体引用。
- 现有公开文件接口按资产 ID 查询，并按媒体状态与授权决定是否公开。
- V3 方案已建议新闻修订保存 `assetId`，并新增新闻修订级图片引用记录。
- 初步结论：文件夹位置和展示名称应属于可变元数据，新闻引用必须绑定稳定资产身份；物理文件路径不能作为业务引用。
- 2026-10-14：用户进一步确认活动相册是否应与媒体资源页面合并。结论是共享同一媒体资产库和选择器，但保留活动相册作为独立业务模块；相册负责活动信息、封面、图片顺序和图注，媒体库负责文件、授权和整理。

#### 根本原因

如果正文保存文件路径或文件夹路径，移动或重命名会造成断链。将新闻绑定到不可变资产 UUID，并让公开接口通过 UUID 解析当前受控文件，可以使整理操作不影响引用，同时允许停用或撤权即时阻断公开访问。

#### 解决方案

待实现：媒体库增加库、父子文件夹、展示名称和移动接口；资产保留不可变 UUID 与内部存储键；新闻修订通过独立引用记录保存封面/正文用途和展示参数。删除采用停用/归档，已被发布修订引用的资产不得硬删除；替换文件默认生成新资产或新版本，不覆盖已发布修订的历史文件。

活动相册复用媒体库资产和授权检查，但继续使用独立的相册修订图片关联，保存封面、顺序和图注；不把活动相册本身改造成媒体文件夹。

#### 验证方法

待实现后验证：移动和重命名后新闻预览、公开详情仍能解析同一资产；停用或撤权后公开图片立即受控下线；历史修订仍保留原引用；删除被引用资产时服务端拒绝硬删除并列出引用位置。
