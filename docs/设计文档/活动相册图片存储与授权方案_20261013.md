# 活动相册图片存储与授权方案

日期：2026-10-13。状态：本地开发方案已实现；云端存储位置待部署时确定。

## 图片放在哪里

- **文件本体**：本地默认放在 `frontend/server/storage/media/YYYY/MM/<随机 UUID>.webp`，目录已从 Git 排除。服务器只把该目录作为受控媒体文件区，不作为静态网页目录。可用环境变量 `MEDIA_ROOT` 指向其他绝对路径。
- **PostgreSQL**：`assets` 保存文件键、尺寸、替代文本、署名、来源与状态；`asset_clearances` 保存版权和人物公开依据；`content_assets` 保存相册修订所引用的图片、顺序和中英文逐图说明。数据库不保存图片二进制。
- **公开访问**：图片通过 `/api/v1/assets/:id/file` 读取；只有状态为 `active` 且版权、人物两项核对仍有效才返回文件。相册即使已发布，也会在每次读取时过滤停用或撤权图片；若没有可公开图片则隐藏相册。
- **云服务器**：首版可把 `MEDIA_ROOT` 指到独立持久化磁盘／挂载卷，例如 `/var/lib/scale-lab/media`，与应用代码目录分离。若将来采用对象存储，需要替换文件读写实现并迁移文件键；当前代码尚未接入任何云对象存储服务。

## 上传与发布流程

1. 后台选择 JPEG、PNG 或 WebP 图片；上传请求限 10 MB。服务端实际解码确认格式，限制输入像素，并缩放至最长边不超过 2400 像素，重新编码为 WebP。文件名由服务器生成，不使用用户上传的原始名称。Sharp 默认输出移除 EXIF 等元数据；本项目按图像方向旋转后再输出。[Sharp 输出文档](https://sharp.pixelplumbing.com/api-output/)、[Multer 文件上传文档](https://expressjs.com/en/resources/middleware/multer/)。
2. 新图片状态为 `pending`。填写中文替代文本、摄影／图片署名和来源；分别登记版权使用依据与人物公开情况。没有可识别人物也要记录核对依据。
3. 两项依据均有效后才能启用图片。相册选择已启用图片，第一张为封面，可调整顺序并填写逐图说明；相册的草稿、核查和发布按中英文独立管理。
4. 停用图片或撤销任一授权时，公开图片接口立即不再返回文件；相册公开响应也同步过滤该图片。文件留在受控目录和审计记录中，供核对和后续处理。

## 备份与迁移

数据库备份和 `MEDIA_ROOT` 文件目录备份必须成套执行、成套恢复，并做恢复演练。部署或容器更新时要挂载持久化目录；不能只备份数据库，也不能把该目录放在会被重新构建清空的代码目录中。图片数量、容量和云服务商尚未确定，云端磁盘还是对象存储将在部署前根据实际规模和运维方式决定。

## 当前边界

相册已支持最多 30 张图片、封面顺序、中英文说明与授权过滤。媒体资源与相册的接口自动联调已通过；真实图片与人物许可仍须实验室逐项确认，旧资料没有自动导入或公开。媒体文件替换、缩略图规格、云端对象存储和备份恢复演练属于后续任务。
