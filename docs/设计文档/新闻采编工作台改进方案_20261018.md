# 新闻采编工作台改进方案

日期：2026-10-18。基线：V4-20261017，提交 6ef64bb。依据：六篇公众号新闻及十一张配图的实际录入、核查、发布与前台验收。

## 一、实际问题与优先级

|问题|影响|安排|
|---|---|---|
|列表只区分草稿/已发布|已公开旧版本同时有新草稿时容易误判|本轮 P0|
|列表最多返回100条，只有搜索|正式新闻混在测试草稿中，无法可靠翻页|本轮 P0|
|保存后统一提示尚未公开|与仍在公开的旧版本矛盾|本轮 P0|
|发布后缺少公开页入口|核对网站效果需要另找新闻|本轮 P0|
|重复点击保存/发布|可能产生重复请求或重复修订|本轮 P0|
|图片提示仅给数量|编辑人员不知道哪张图片需要处理|本轮 P0|
|原文来源署名需要手动排版|转载文章缺少统一的公开来源模板|后续 P1|
|论文图在移动端阅读困难|需要图片放大查看|后续 P1|
|六篇导入依赖专用脚本|普通人员难以复用批量采编流程|后续 P2|

## 二、本轮实现范围与接口

1. 中文新闻列表增加状态、排序和分页。每页20条；可按最近编辑或新闻日期排序，日期排序默认从新到旧；稳定追加 ID 排序。
2. 状态由最新中文修订与中文公开修订比较得出：草稿、已核查待发布、已发布、有新草稿（旧版仍公开）。英文独立修订不应误判为中文新草稿。
3. `GET /api/admin/v1/news` 增加 `state=all|draft|ready|published|changes`、`sort=updated|date`、`page`、`pageSize`（最大100），保留 data 数组，meta 返回 total/page/pageSize。无分页参数时保持100条兼容上限。非法参数返回400。
4. 详情增加 publishedRevisionId、currentPublished，保留 published（该语言存在公开版本）。不修改数据库结构，不改变公开页排序，也不修改既有文章内容。
5. 编辑页持续提示当前草稿和公开版本关系，提供“查看公开页”；保存提示明确说明旧版仍公开。已公开当前修订时禁止重复点击发布。
6. 保存/核查/发布/撤回进行中锁定新闻表单和离开入口，完成或失败都解锁。保留并发版本冲突保护，不合并核查与发布。
7. 图片问题列出文件展示名，封面可选、核查依据两项均可不填的规则保持有效。

## 三、后续阶段设计

- P1 公开来源：增加可选来源名称、原文链接、原文发布日期，与仅后台可见的核查依据分开；随修订保存，前台及预览共用页尾模板。旧稿已手工署名，不自动重复追加。
- P1 图片阅读：公开新闻图片支持键盘关闭、焦点恢复、移动端缩放/大图查看；媒体授权撤销后仍执行现有访问限制。
- P2 采编：设计导入预览、重复来源检测、图片用途选择和逐篇结果报告，再考虑批量核查发布；不自动抓取并直接公开任意公众号内容。
- 动图支持需要单独决定大小、格式、存储和无障碍策略，本轮不改变静态图片转码机制。

## 四、验收要求

- 用隔离测试新闻覆盖草稿→核查→发布→新草稿→重新发布→撤回，并确认旧版在新草稿保存后仍公开。
- 验证筛选、分页无重叠、total、非法参数，以及英文修订不影响中文状态。
- 浏览器检查筛选、公开入口、编辑状态、重复操作锁定和手机宽度；不更改六篇正式新闻。
- 更新进度/测试记录并推送同一 V4 分支；本轮完成不等于 P1/P2 已实现。
