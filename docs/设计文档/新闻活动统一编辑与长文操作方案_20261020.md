# 新闻活动统一编辑与长文操作方案

日期：2026-10-20。依据：用户要求合并活动相册与新闻、改善图文混选和长文操作、增加回到顶部。

## 一、统一编辑与展示规则

后台统一入口为“新闻/活动”，复用原新闻的富文本、媒体库、实时预览、历史修订、并发版本校验、核查、发布和撤回功能。

| 发布位置 | 首页概览 | 全量入口 | 完整图文 |
| --- | --- | --- | --- |
| 新闻动态 `news` | 最新动态，最新3条 | 新闻动态页 | `news.html?slug=…` |
| 实验室活动 `activity` | 实验室现场，最多3张活动封面 | 实验室文化页 | 共用图文详情，返回实验室文化 |

- 发布位置为必填下拉框；列表支持全部、新闻、活动筛选，并保留状态分区、搜索、业务/测试筛选和每页10条。
- 活动增加选填地点，使用同一日期字段排序；新闻摘要最多500字，活动最多1000字；来源链接和说明均选填。
- 活动正文可以自由穿插文字与媒体库图片。显式封面优先；未选封面时，活动概览使用正文第一张可公开图片。
- 活动文化页展示简介、照片和完整图文入口；详情遵循编辑器的图文顺序、字体档位和图片布局。
- 保存草稿不改变网站。修改发布位置也必须核查并重新发布才切换栏目，避免一次修改同时出现在两个位置。
- 双语仍独立核查发布；中文切换发布位置或日期后，清除共享事实已不一致的英文公开版本，需重新核对英文。

## 二、数据库及接口

统一存储为 `content_items.type='news'`，以每个修订的 `news_revisions.category` 决定发布位置；新增 `news_revisions.location`，富文本仍保存在本地化 `extra_json.richText`，图片引用仍由 `news_revision_assets` 管理。

采用011迁移：

1. 检测新闻与旧活动的URL标识冲突，有冲突则整体失败，要求明确处理，不擅自更名。
2. 为旧活动每个历史修订补齐统一图文元数据，文字段落在前，原图片顺序在后；保留图注和首图封面。
3. 保留内容ID、修订ID、版本号、标题、摘要、原纯文本、来源、核查状态、发布指针及媒体授权；内容类型统一为news。
4. `activity_revisions`、`content_assets` 留作历史资料，后续编辑只写统一结构。迁移由既有事务和迁移校验和机制管理。

| 接口 | 用途 |
| --- | --- |
| `/api/admin/v1/news` 及原有子路由 | 统一增改、预览、历史、核查发布撤回；新增 `category`、`location` |
| `/api/admin/v1/news?category=all\|news\|activity` | 按最新中文修订的位置筛选，分页和状态计数一致 |
| `/api/v1/news`、`/api/v1/home` | 仅公开新闻分类 |
| `/api/v1/activities` | 仅公开活动分类，含图文、地点、封面、可公开图片 |
| `/api/v1/news/:slug` | 统一完整图文详情 |
| `/api/v1/activities/:slug` | 保留活动详情接口，新闻类型返回404 |
| `/api/admin/v1/activities` | 旧编辑接口退役，返回410并提示统一入口；不能继续生成第二套内容 |

所有公开集合读取发布指针，不能读最新草稿。图片仍需媒体库启用及授权；未授权图片可后台编辑，不能通过核查发布，已停用图片立即从公开媒体映射移除。

旧活动导入脚本已适配统一接口，仍只上传待核媒体、创建草稿，拒绝覆盖人工编辑。旧相册联调用例由 `test:news-activities` 替代；`test:media-albums` 命令别名也指向新流程。

## 三、编辑体验

- 图片优先参与选择；取消默认图片拖动，避免抢占跨段落拖选。调整图片位置使用剪切、粘贴。
- 混合选区中的图片增加清晰高亮，增加“全选图文”，保留Ctrl/⌘A及复制、剪切、粘贴、删除和撤销。
- 工具栏鼠标按下时保留编辑选区。内部图片复制粘贴保留资产ID、图注、宽度和对齐；空图注不会误存编辑提示。
- 编辑卡片顶部固定显示状态、保存和返回列表。底部保存/核查/发布操作栏随滚动可用，桌面格式工具栏吸顶；手机避免格式工具栏占满屏幕。
- 沿用未保存离开确认和处理中按钮禁用，顶部保存与原保存使用同一表单。

## 四、回到顶部

当前公开站全部页面及工作台加载共享组件。下滚360px后显示右下按钮，顶部隐藏；支持键盘焦点和中英文标签，系统减少动画时直接滚动，手机保留安全边距。

## 五、本轮交付边界

统一编辑、展示路由、数据迁移和定向回归已实现。毕业合影、东湖活动维持用户待审草稿及原照片待核状态，本轮不代替用户发布。原新闻人工修改不从seed回写。代码、PostgreSQL数据和storage上传文件仍需分别备份。
