# V5 架构评审核实与工程化改进方案

日期：2026-10-27。状态：方案，尚未开展业务代码重构。

## 一、范围与结论

依据用户提供的《SCALE Lab 实验室网站代码架构评审》，对照当前本地 `V5-20261020` 工作区核实。原评审对象为提交 `8259bcb`，不包含本地后续未提交的视觉、登录页、开屏动画及 Pages 展示导出工具。

本轮执行源码核实，不将历史测试通过记录视作本轮重新运行通过；不修改数据库、不移动目录、不重新导入已编辑内容、不自动提交或推送。

保留 Node.js + Express + PostgreSQL、原生公开前端、现有修订与发布模型。以保护数据、建立回归、优化明确问题、整理结构、准备正式部署为主线，不做全站重写。

## 二、评审意见核实

| 意见 | 本轮结论 | 处理方向 |
| --- | --- | --- |
| 后端放在 frontend，原型与正式代码混杂 | 属实；`platform.js` 服务正式公开站，`server.js` 为旧原型 | 明确唯一运行入口，再分批归档和迁移目录 |
| 成员列表存在 N+1 查询 | 属实；`members.js:listPublic` 遍历成员，逐个读取修订、权限与图片 | 批量查询和批量媒体授权解析 |
| 成员详情先加载所有成员 | 属实；详情调用 `listPublic(..., true)` 后 find | 根据 slug、语言和公开授权直接定位目标 |
| 新闻列表携带全文 | 属实；列表 SELECT 包含 `l.body`，且无公开服务端分页 | 轻量分页列表，详情保留全文 |
| 活动列表返回所有富文本与图片 | 属实；还逐条调用 revisionMedia | 首页封面概览、文化页相册概览、单篇详情各取所需 |
| 活动摘要被 maxlength=500 阻挡 | 原评审遗漏运行时逻辑；`app.js:109` 已按活动/新闻动态设置 1000/500，旧提交也已有 | 不是已确认缺陷；补类别切换和临界值回归，避免重复修复 |
| 缺乏生产部署与备份闭环 | 属实；本地 Compose 有 PostgreSQL 命名卷，但不等于备份，仓库未见成套自动备份/恢复工具 | 增加成套备份、隔离恢复、云端容器与代理配置 |
| 登录限流仅在进程内 | 属实；`failedLogins` 为 Map | 限制过期记录和容量；正式环境采用共享限流状态或代理与应用分层保护 |
| 代理与安全配置不完整 | 属实；Cookie Secure 判断直接读取转发头，需与实际信任代理拓扑统一 | 生产配置集中化、可信代理边界、HTTPS 与 Cookie、响应头验证 |
| 缺少可见 CI | 属实；有测试脚本但未见 Actions 工作流 | 临时数据库、隔离媒体目录、构建与关键链路回归 |
| 必须换 Python / 前端框架 / 数据库 | 不采纳 | 当前功能规模不构成换栈理由 |
| 必须分离编辑者与审核发布者 | 不采纳为首期要求 | 用户已确认少于 5 人，允许同一人编辑、核查、发布，继续保留审计 |
| GitHub Pages 不能运行完整后台 | 判断正确，但当前已另外部署静态展示版 | 保留 gh-pages 公开快照，动态平台继续独立建设 |

补充：`news-smoke.js` 默认端口仍为 3001，部分历史测试配置与当前固定 3004 约定不一致。测试应统一配置入口，并强制写入型测试使用明确的隔离环境，不能为通过测试向真实资料库写数据。

## 三、优先级与实施顺序

这里区分“当前本地开发需要马上做”与“完整后台公网开放前必须完成”。当前 Pages 展示不运行后端，不能把后端生产加固描述为静态展示站已暴露的漏洞。

### 阶段 A：数据保护与可复现基线

1. 清点 V5 未提交改动，区分此前视觉成果、本轮 Pages 工具及后续重构，分别记录验收和提交；经用户授权时推送 V5，不以 gh-pages 代替源代码备份。
2. 建立数据库与媒体成套备份：数据库逻辑备份、实际上传目录、校验清单、迁移版本与应用版本，记录内容修订/发布/图片授权。
3. 制定一致性窗口：备份期间阻止后台写入及上传，或采用可验证的一致性策略，不能一边修改资料一边把文件和数据库随意拼成备份。
4. 先恢复到独立数据库和独立媒体目录。验证文章、成员、修订、授权、图片引用与文件校验，绝不默认覆盖当前资料库。备份失败必须明显报错，不把空文件当成功。
5. 明确真实资料库和测试库边界，建立统一 TEST_BASE_URL 配置；测试使用独立数据库、管理员与媒体存储。

验收：能够从一组备份恢复可运行副本，新闻、活动及图片均可读；真实环境不出现新测试记录。备份文件含个人资料、认证记录等，不推送 GitHub 或放入公开静态目录。

### 阶段 B：先建立自动检查，再优化查询与接口

1. CI 使用临时 PostgreSQL，`npm ci`、迁移空库、重复执行迁移、编辑器构建、语法检查与关键 API 测试；随后接入浏览器关键链路。构建失败阻止发布，不直接连接本地真实数据库。
2. 成员列表批量读取已发布的当前语言修订、字段授权和有效头像。详情按 slug 读取，保留未授权资料不可见、邮箱/校友去向独立授权、照片停用立即生效等既有规则。
3. 新闻列表返回标题、摘要、日期、slug 等轻量字段，支持分页、年份、关键词；首页只取最新 3 条。详情返回全文和媒体信息，支持旧公开版本与新草稿分离。
4. 首页活动只取最新 3 个活动及封面；文化页保留当前可见照片和全文入口，避免精简接口时把现有相册效果丢掉。可按概览/相册/详情定义返回结构，批量解析图片；不机械地将全部图片搬到详情页。
5. 若活动或成员数量增长，再依据实际 SQL 执行计划补索引，先验证现有索引，不预设每张表都需要新增。
6. 摘要规则统一为共享常量或共享校验契约，测试 500/501、1000/1001 边界、打开旧活动以及类别切换。由活动切为新闻时应提示超长，不能静默截断。

特别依赖：公开列表由全量改为分页时，必须同时更新公开新闻筛选/页码、首页请求、活动消费端、静态导出器和测试。导出器需要遍历全部页并校验总数，不能只保存第一页。已有 Pages 快照保持可用，新快照验收后才更新。

验收：成员列表查询次数不随人数线性增长，详情只查询目标；分页不漏项、不重复，首页最多 3 条；公开授权/双语/修订规则不退化；新导出与动态站公开内容一致。

### 阶段 C：整理目录与复杂模块

建议采用易读的目录，不要求引入 monorepo 框架：

```text
SCALE Lab/
├─ frontend/
│  ├─ public/       # 当前正式公开站，去掉 visual-preview 日期命名
│  ├─ admin/        # 当前管理后台
│  └─ shared/       # 浏览器共用组件
├─ backend/         # 当前 frontend/server
│  ├─ src/
│  ├─ db/
│  ├─ scripts/
│  └─ tests/
├─ archive/         # 确认可归档的旧网页与旧 JSON 原型
├─ infrastructure/  # 本地、测试、生产环境配置
└─ docs/
```

先建立路径配置和启动命令，随后分批搬动并验收。不一次移动目录又重写业务。浏览器现有 URL 不变；脚本中的项目根目录、素材路径、测试路径、storage、导出输出与独立部署 Git 元数据路径一并清点。

历史导入素材与数据库迁移不能当作废弃文件删除。运行中的存储数据、Docker 卷与用户编辑内容不能随目录整理丢失。

复杂模块优先从新闻/活动和媒体入手，按实际边界分为路由/校验、工作流服务、数据库访问；不强制每个模块拆成同样的五六个文件。分离 Express app 创建与 listen，便于在隔离环境测试。

验收：新维护者能从 README 找到前后端与唯一启动命令；固定端口 3004；公开 URL、后台编辑、媒体读取、导出部署及恢复工具均可用。

### 阶段 D：完整后台正式部署前的门槛

- 提供生产 Dockerfile/Compose、示例环境配置、媒体持久化挂载、数据库内网连接、健康检查与迁移步骤；不自动购买云服务。
- 区分开发与生产，限定可信反向代理来源。Cookie Secure 由受信任的 HTTPS 状态或明确生产配置决定，不直接信任任意转发头；配置 HTTPS、适当的 CSP/HSTS，并验证编辑器、图片与动画能正常工作。
- 当前弱口令仅限本地演示，生产使用单独强口令和密钥，不复制示例密码。上线配置应校验缺失项并拒绝带着不完整配置运行。
- 登录限流与请求大小控制、审计与错误日志、正常停机与连接关闭、备份任务失败告警形成闭环。可先利用 PostgreSQL/反向代理，不因小规模 CMS 直接引入 Redis 等额外组件。
- 先在云端测试环境恢复一份数据并演练应用版本回退。数据库采用可兼容的前向迁移，不随意回滚历史表结构。

验收：全新环境可依文档部署，HTTPS 登录与上传发布通过；限流有效；重启后内容和图片保留；备份可恢复；未完成的功能不宣称为生产验收通过。

### 阶段 E：按维护收益继续改善

为输入、接口与工作流逐步补 JSDoc/类型检查；只有确有维护收益时迁移 TypeScript。后台是否采用 Vue/React、公开站是否静态生成、是否新增 Python AI 服务，后续按需求决定，不属于本轮必做项。

## 四、执行边界

继续在 V5 开发，不改写历史提交，不自动切换语言或数据库，不清空测试或业务数据。目录重组和接口变更均以已有功能、媒体授权与双语发布规则为回归边界。

下一步建议从阶段 A 开始：梳理并保存源码基线，落地备份/恢复工具和隔离测试环境，再进入批量成员查询和轻量新闻接口。正式云部署目标平台、域名和备份保留策略可在阶段 D 实施前确认，不阻碍当前基础工作。
