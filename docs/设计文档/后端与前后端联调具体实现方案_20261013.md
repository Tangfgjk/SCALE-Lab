# 后端与前后端联调具体实现方案

更新日期：2026-10-13。状态：开发实施基线。配套进度见[后端与前后端联调进度跟踪](../进度文档/后端与前后端联调进度跟踪_20261013.md)。本文描述首版完整目标；截至本次更新，新闻、研究内容、成员、媒体、活动相册、站点设置与本地账号的基础链路已实现；完整内容与页面验收按进度表继续推进。

## 1. 已确认决定与交付目标

- 公开站以 `frontend/visual-preview-20261013` 的学术编辑式设计为正式实现基线；保留现有交互，接入真实内容时微调排版。原版暂留作对照。
- 后台采用 `frontend/admin-prototype.html?variant=A` 的侧栏工作台布局。原型中的示例账号、表格和按钮均不得作为正式功能。
- 首版完整范围：成员、新闻、论文、项目、研究方向、活动相册、媒体库、站点设置、操作记录、账号管理。中文优先，英文可并行录入，但需单独核查后发布。
- 本地与云端统一 PostgreSQL。管理员与指定内容人员合计不超过 5 人；登录后均可编辑、核查、发布、撤回；仅管理员管理账号，所有关键操作留痕。
- 开发沿用 Node.js、Express 和静态 HTML/JS；同一 Express 进程提供页面、公开接口和后台接口。当前没有足以要求换用前端框架的功能依据。

**可交付结果**：获准人员从后台录入来源明确的内容，保存草稿、预览、检查、发布或撤回；公开 API 和所选公开站只显示对应语言的已发布版本；更新草稿不改变官网；图片及个人信息按授权即时过滤。

| 管理接口 | 六类内容及设置的双语草稿、核查、发布、撤回、修订历史和审计已接入；本地账号启停、角色、改密已接入 | 媒体替换、审计分页与学校统一身份入口 |

## 3. 模块、接口与责任

```text
浏览器公开站 ── 同源 /api/v1 ──┐
                               ├─ 内容发布模块 ── PostgreSQL
后台 A 工作台 ─ /api/admin/v1 ─┘       │
         │         │                     └─ 媒体文件存储
         └─ 会话与 CSRF ─ 身份模块
```

| 模块 | 对调用方提供的接口 | 内部承担的规则 |
| --- | --- | --- |
| 身份模块 | `requireUser`、`requireAdmin`、登录／退出／当前账号 | 本地专用账号适配器先落地；未来学校统一身份入口接入同一用户标识；停用账号立即失效 |
| 内容发布模块 | `saveDraft`、`check`、`preview`、`publish`、`withdraw`、`listPublished` | 修订快照、版本冲突、类型校验、语言状态、来源和授权检查、公开字段裁剪、事务与审计 |
| 内容类型实现 | `validate`、`toPublicView`、类型专用详情读写 | 新闻、论文等字段与公开呈现各不相同，不做单一万能表单 |
| 媒体模块 | `upload`、`updateClearance`、`listUsages`、`disable`、`resolvePublicAsset` | 文件类型／大小限制、替代文本、版权及人物授权、引用追踪；停用后不再生成公开地址 |
| 设置模块 | `saveDraft`、`preview`、`publish`、`readPublic` | 名称、Logo、简介、首页标题、文化页标题／愿景／价值观、邮箱、首页精选、统计数字和统计口径的修订与发布；中英文按语言独立核查 |
| PostgreSQL 存储适配器 | 对内容模块提供事务和查询实现 | 连接池、SQL、迁移、约束；公开页面不直接访问数据库 |
| 文件存储适配器 | 媒体模块内部使用的写入与读取接口 | 本地开发目录与云端对象存储可替换；是否启用云存储以后再定 |

内容发布模块是共用规则的唯一入口：列表页、编辑页和公开 API 不各写一份“已发布”判定。存储和认证的替换点只放在确有两种运行方式的地方，避免为每张表建立重复转发层。

目标目录与当前落地文件（实施时可在不改变接口的前提下细化）：

```text
frontend/
  visual-preview-20261013/ # 已选公开页面；新闻区已接 API
  admin/                    # A 布局、登录与新闻专用编辑页面已落地
  server/
    platform.js             # 当前 Express 入口、静态页面、错误处理
    auth.js                 # 本地身份、会话与 CSRF
    news.js                 # 新闻专用读写与发布流程
    research.js             # 研究方向、论文、项目
    members.js              # 成员资料与公开授权
    db/migrations/          # 顺序执行且记录版本的 SQL
    db/pool.js              # PostgreSQL 连接与事务
    content/                # 后续共用发布模块与类型实现
    media/                  # 元数据、授权与文件存储适配器
    routes/public.js        # /api/v1
    routes/admin.js         # /api/admin/v1
    scripts/                # 管理员初始化、候选内容导出
    tests/                  # 发布事务、权限及接口联调
```

## 4. 数据库落地与修订语义

详细逻辑字段沿用[数据库结构与发布状态设计](数据库结构与发布状态设计_20261013.md)，实施时按下面顺序迁移：

1. `admin_users`、`admin_identities`、本地密码凭据与会话表、`schema_migrations`。密码只存加盐哈希；会话存失效时间和撤销时间。学校身份入口以后将其身份绑定到同一 `admin_users.id`。
2. `content_items`、`content_revisions`、`content_localizations`、`content_publications` 与各类型修订详情表。UUID 主键；`timestamptz` 存时间；`(type,slug)`、`(content_id,version)`、`(content_id,locale)` 等唯一约束，公开指针用复合外键保证修订属于本内容。
3. `content_sources`、`content_relations`、`member_permissions`、`assets`、`asset_clearances`、`content_assets`。文件本体不入数据库；旧修订的媒体顺序不被新草稿改动。
4. `site_settings`、`site_setting_revisions`、`site_setting_publications`、`audit_events`。设置使用单例全局版本、中英文独立修订和公开指针；审计记录操作者、对象、动作、时间和结果，不保存明文密码或授权材料正文。已由 `005_site_settings.sql` 落地。

**修订规则**：每次成功保存产生不可变的新修订并递增 `content_items.version`。新闻与研究内容的当前实现是每次修订只写一种语言，同时保存该语言本次核对的共享事实；后台按语言寻找最新修订，不依赖全局 `current_revision_id`。中文关键事实改变并发布后，相关英文公开指针在同一事务内移除，英文需重存、重核、重发。`content_publications(content_id,locale)` 是公开查询的唯一权威指针；`content_items.status` 仅作后台列表的派生摘要，不得据此把草稿输出到官网。发布、撤回、审计在同一事务中完成；撤回英文只移除英文指针，撤回中文时也撤回英文。

**并发与幂等**：保存和发布请求提交 `expectedVersion`；不一致返回 409 和当前版本，不覆盖别人的编辑。重复发布同一修订应得到可解释的“已发布”结果且不产生第二条公开指针。外键、唯一约束及日期顺序在数据库层保护，复杂业务校验在发布模块完成。

## 5. 后台 A 布局与完整编辑能力

公共界面：登录／退出、工作台、内容列表（筛选、搜索、分页、状态）、草稿保存、中文／英文切换、发布前检查、公开页预览、发布／撤回、修订历史、来源记录、操作记录。用户可兼任编辑和发布；发布前检查的错误需阻断，警告需显示并记录处理结果。

| 模块 | 专用编辑区 | 公开前必须检查 |
| --- | --- | --- |
| 成员 | 类别、姓名与称谓、简介、研究兴趣、排序、个人链接、照片、邮箱、校友去向；逐字段公开开关 | 身份、照片／简介／邮箱／去向的授权，链接有效 |
| 新闻 | 标题、摘要、正文、事件日期、分类、封面、关联成果 | 事件与发布时间分开；事实来源、图片与外链 |
| 论文 | 原题、作者顺序、期刊／会议、年份、发表阶段、DOI、链接、精选、关联方向 | DOI 跨内容查重；未来年份不能默认“已发表” |
| 项目 | 正式名称、编号、资助类别、负责人、起止日期、项目进度、介绍、关联成果 | 编号与项目状态来源；结束日期不早于开始日期 |
| 研究方向 | 中英文题名与简介、子主题、排序、相关人员／论文／项目 | 对外三类或四类方向的最终口径；关联内容已公开 |
| 活动相册 | 活动名、日期、说明、封面、批量选图、逐图说明与替代文本、拖动排序 | 每张图片的版权和涉及人物授权；停用图不能公开 |
| 媒体库 | 上传、预览、来源、授权、引用位置、替换和停用 | 文件格式／大小、公开许可、替代文本和已发布引用 |
| 站点设置 | 名称与 Logo、简介、邮箱、首页精选、统计数值及口径、双语状态 | 联系方式和统计来源；Logo 与媒体授权 |
| 操作记录／账号 | 按时间、人员、对象筛选记录；管理员启停账号及角色 | 内容人员不能操作账号；停用立即阻断会话 |

字段与必填项以真实样本进一步细化，但以上能力是首版范围，不因先做新闻纵向联调而删减。

## 6. HTTP 契约与错误处理

统一成功体 `{data, meta, requestId}`；错误体 `{error:{code,message,fields},requestId}`。列表明确 `page`、`pageSize`（上限 50）、`total` 和稳定排序。时间用 ISO 8601，语言使用 `zh`／`en`，对外路径保留 `/api/v1`；缺失的英文已发布内容返回空列表或 404，不自动混入中文草稿。

| 类型 | 路径与动作 | 结果 |
| --- | --- | --- |
| 会话 | `POST /api/admin/v1/session`、`GET /api/admin/v1/me`、`DELETE /api/admin/v1/session` | HttpOnly 会话 Cookie；登录或 `GET /me` 返回 CSRF 令牌，写请求放请求头验证；401 未登录、403 无权限 |
| 内容 | `GET /contents?type=&status=&page=`、`POST /contents`、`GET /contents/:id`、`PUT /contents/:id/draft` | 列表／详情／新修订；`expectedVersion` 冲突返回 409 |
| 工作流 | `POST /contents/:id/check`、`GET /contents/:id/preview?locale=zh`、`POST /contents/:id/publish`、`POST /contents/:id/withdraw` | 检查不写公开指针；发布传修订 ID、语言和期望版本；撤回写原因 |
| 历史与来源 | `GET /contents/:id/revisions`、`GET/PUT /contents/:id/sources` | 草稿、已发布版本与核验记录；仅后台可见 |
| 媒体与设置 | `/assets`、`/settings` | 上传／引用／授权／停用；设置草稿与发布 |
| 管理 | `GET /audit-events`、`GET/POST/PUT /users` | 记录只读；账号写操作仅管理员 |
| 公开 | `/api/v1/home`、`/members`、`/news`、`/publications`、`/projects`、`/research-directions`、`/activities` | 只输出公开指针、授权字段与可用图片；详情不存在或未发布均为 404 |

输入按类型验证长度、日期、URL、枚举和引用 ID；错误字段以稳定路径返回，例如 `fields.titleZh`。禁止从客户端提交 `published_by`、审核结论或审计记录。公开接口不得返回内部修订 ID、来源凭据、个人私有字段、草稿或账号资料。

## 7. 前后端联调与数据迁移

1. 先建立页面与接口字段映射表。将 `window.LAB.lab/directions/stats/gallery/news`、成员和成果字段对应到 `/api/v1`；统一 `fetch` 读取层，不在每页复制请求和错误处理。
2. Express 在本地同源提供已选公开页面、后台页面与 `/api`，避免开发时用 8080 页面跨端口读 3000 API。8080 仍可作为纯视觉预览，**不能**当成已联调环境。
3. 首个纵向路径选新闻：后台保存草稿 → 检查来源 → 预览 → 发布 → `/api/v1/news` 和首页显示 → 再编辑时仍显示旧版 → 新版发布才更新 → 撤回后消失。完成后移除优化副本该模块的静态 `data.js` 依赖。
4. 依次接研究方向、论文、项目、成员、活动相册与站点设置。首页统计必须有来源和口径；无已发布内容时隐藏栏目或显示恰当空状态。照片停用或授权撤回后即使旧修订仍指向它，也不能继续输出图片。
5. `data.js` 和 `content.json` 先导出为候选清单，逐条比对同名、同 DOI、同编号、研究方向差异与 `@@@`。每条记录保留原始来源、核验人、核验日期和处理结论；默认仅导入草稿，禁止自动公开。用户提供的教师主页可做事实来源，不自动证明本站取得图片与个人信息再展示许可。
6. 英文结构可同步做；仅英文文本、共享事实和授权均经核验后才公开英文条目。中文发布不等英文完成。

## 8. 安全、部署与验证

- 本地专用账号先用于开发与首版，保留接学校统一身份认证的身份绑定结构；具体入口确定后再集成。所有管理写接口校验会话、角色与 CSRF，限制登录尝试，上传检查真实 MIME、文件大小和扩展名；密码和密钥只放环境变量／密钥管理。
- 本地和云端使用同一 PostgreSQL 迁移。迁移记录版本且可在空库重复执行；部署先迁移再启动。正式环境使用 HTTPS、最小权限数据库账号、数据库备份及恢复演练、媒体文件备份、访问日志和错误监控。
- 必做验证：数据库约束与事务；未登录／普通账号／停用账号；版本冲突；草稿与公开隔离；双语状态；来源与授权阻断；图片停用；所有模块发布／撤回；公开页桌面与 390px 手机、键盘操作及错误／空状态。
- 原型演示数字不进正式数据库种子。开发种子只用于本地并明确标记；端到端验收用经核验样本，不以假数据填满官网。

## 9. 实施顺序与完成标准

| 里程碑 | 范围 | 完成标准 |
| --- | --- | --- |
| M0 数据核对与环境 | 两份旧数据差异、PostgreSQL 连接、字段映射 | 候选清单与风险可追踪；空库迁移可运行 |
| M1 后台基础与新闻闭环 | 会话、A 工作台、核心表、新闻草稿／发布／撤回、公开新闻 API 和首页 | 一人可完成端到端新闻流程；草稿隔离、审计与撤回通过 |
| M2 学术内容 | 方向、论文、项目、成员及专用编辑区 | 来源、DOI／编号、成员字段授权和双语检查通过 |
| M3 媒体与设置 | 相册、媒体库、站点设置、首页精选 | 图片引用／排序／授权撤回和设置发布通过 |
| M4 收敛与验收 | 所有公开页移除旧静态数据依赖，账号管理、完整回归与云端准备 | 功能矩阵全绿、内容核验完成、备份恢复演练通过 |

任一里程碑需同时具备可操作页面、接口结果、数据库状态和验证记录；只完成表结构或静态页面不算完成。外部待确认项见[项目目标与待确认决策](../项目规划/项目目标与待确认决策_20261013.md)，不会阻止 M0/M1 的本地开发，但会影响真实内容公开和云端发布。
