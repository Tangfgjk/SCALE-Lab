# 内容平台数据库结构与发布状态设计

更新日期：2026-10-13。状态：首版概念与逻辑模型。**实际已执行的表结构以 `frontend/server/db/migrations/001_core.sql` 至 `006_site_editorial.sql` 为准**；下方表格同时列有尚未实现的目标字段和模块，不能当作当前数据库快照。已确认本地开发和未来云服务器统一使用 PostgreSQL；云厂商和运行方式待定。其主键、外键、唯一约束和检查约束可以在数据库层保护关键关系；参见[PostgreSQL 约束文档](https://www.postgresql.org/docs/current/ddl-constraints.html)。

## 1. 建模原则

- 一份内容源供后台、公开接口和网站读取；现有 `data.js` 与 `content.json` 仅作迁移输入。
- 内容的**发布状态**与项目的**业务进度**分开；中文与英文的公开就绪状态分开。
- 公开版本与正在编辑的草稿修订分开保存，避免编辑到一半就改变官网内容。
- 数据库保存结构化内容和图片元数据；图片文件本体放文件存储。来源凭据和授权材料为后台内部数据，不进入公开响应。
- 关键关系用外键，稳定标识用 UUID，唯一业务标识加唯一约束；复杂发布检查由内容模块执行并留痕。

## 2. 核心表与关系

`content_items` 是所有可发布内容的共同记录。每次编辑产生一条不可变的 `content_revisions`；各类型详情表与本次修订一对一关联。中文和英文可分别指向已发布修订，公开查询只读这些指针。

## 3. 版本与语言如何工作

`content_items.status=published` 代表存在一个可公开的中文版本，是后台列表所需的摘要；公开接口一律只读取 `content_publications` 指向的修订。每次编辑创建新的 `content_revisions`，并更新 `current_revision_id`；即使当前又有未发布的草稿，旧公开指针仍有效。首次发布必须先完成中文版本。发布操作在一个数据库事务中完成校验、切换该语言的公开指针、更新状态和写入审计记录。撤回指定语言时只移除该语言公开指针并记录原因；整条归档时才同时移除中英文指针。中文指针移除后英文也需同步撤回，以维持英文不得独立于中文公开的约束。

当前新闻、研究方向、论文、项目与成员采用**每次修订只保存一种语言**的实现：全内容共用递增版本号，读取指定语言时按版本寻找该语言最近修订；中英文分别核查，并由 `content_publications(content_id,locale)` 独立指向已发布修订。`current_revision_id` 仅记录全局最近修订，不能用它直接读取某语言的后台草稿。若某内容没有已核查的英文版本，英文列表隐藏该条；中文版本不受影响。英文首次发布要求中文已发布，且关键共享事实一致；中文发布新修订若改变关键事实，则在同一事务内移除旧英文公开指针并记录失效审计。新闻的关键事实为事件日期和分类；方向为编号；论文为年份、发表阶段、DOI 与外链；项目为编号、状态、起止日期；成员为中文姓名、英文姓名、类别、链接、邮箱与排序。英文需按新事实重新保存和核查才能再发布。成员逐字段授权在公开读取时检查，撤销档案授权立即撤销双语发布。站点设置也按语言独立核查与发布，共享事实为联系邮箱、Logo、首页精选及统计数值与来源。

`current_revision_id` 指向的详情、翻译和媒体关系只供后台编辑；公开展示应从指定语言的已发布修订构造结果，避免草稿意外泄露。

## 4. 关键索引与校验

- 索引：`content_items(type, status, display_order)`、`content_publications(locale, published_at DESC)`、`content_revisions(content_id, version)`、`audit_events(created_at DESC)`；实际查询形态确认后再优化。
- 唯一：`(type, slug)`、`assets.storage_key`、后台登录身份 `(provider, provider_subject)`；DOI 和项目编号要按不同内容去重，但同一内容的历史修订允许重复，故在发布校验或另设规范化登记表中实现。
- 发布前：中文必填字段、来源、必要的字段授权、图片替代文本、公开链接格式与项目日期由内容模块核查；数据库负责能表达的非空、唯一、外键和日期顺序约束。
- 删除：内容以归档和撤回为主；被内容引用的资产不得直接物理删除。授权撤回需要使相关公开图片或字段立即失效；公开图片查询需同时检查 `assets.status` 和适用的 `asset_clearances`。
- 迁移：现有 JSON 中的 `@@@` 进入草稿或待核查清单，不进入已发布数据；导入前统一前后端重复条目和 slug。
