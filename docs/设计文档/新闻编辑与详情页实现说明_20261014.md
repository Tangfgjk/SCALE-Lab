# 新闻编辑与详情页实现说明

更新日期：2026-10-14。依据：用户在本地体验内容工作台后确认的新闻编辑流程。本文件记录新闻模块的现行决策；早期文档中“每条新闻必须填写事实来源”的表述，以此处为准。

## 编辑字段

| 字段 | 现行行为 | 公开展示 |
| --- | --- | --- |
| URL 标识 | 系统新建时生成 `news-日期-随机码`，创建前可调整；只接受英文小写、数字和连字符，创建后固定 | 构成 `news.html?slug=...` 详情链接 |
| 语言 | 必填，先创建中文，再按语言分别编辑、核查和发布 | 访客只看到已发布的对应语言版本 |
| 标题 | 必填，最多 200 字 | 首页和详情页 |
| 摘要 | 必填，最多 500 字 | 首页和详情页导语 |
| 正文 | 必填，最多 30000 字；纯文本，保留换行 | 详情页 |
| 事件日期 | 必填，区别于发布时间 | 首页排序和详情页 |
| 分类 | 工作台不展示；服务端默认 `news` | 暂无分类展示或筛选 |
| 核查依据：来源链接／说明 | 均选填，允许全部留空；若填写链接须为 `http(s)` 地址 | 不进入公开 API；仅后台记录 |

来源字段放宽仅适用于新闻。没有外部网页的实验室原创新闻可以不填；编辑人员仍须在发布前检查标题、时间和正文，后台保留核查人、核查时间与发布操作记录。其他内容类型的来源、媒体授权和公开条件维持原规则。数据库 `content_sources` 对有填写依据的修订保存记录；两项均空的新闻修订不创建该来源行，无须修改既有表约束。

工作台各常用表单同时显示“必填／选填”标记；其他模块仍要求来源链接和说明二选一时，标记为“二选一必填”。研究方向仅发布已核准名称时，摘要仍是选填，切换至论文或项目后变为必填。关键字段另附用途说明，避免把项目状态和内容发布状态等概念混用。

## 公开路径与状态

保存草稿 → 核查当前修订 → 发布中文／英文 → `/api/v1/news?locale=...` 显示在首页最新动态 → 标题或“阅读全文”打开 `news.html?slug=...`。详情页从 `/api/v1/news/:slug?locale=...` 读取已发布修订。未发布、已撤回或该语言尚未发布时，公开 API 返回 404，详情页展示不可用提示，不读取后台草稿。重新编辑仍保留旧版公开内容，直至新版完成核查和发布。

首页“精选新闻标识”为空时，显示公开新闻，按事件日期倒序；配置精选后仅显示所选条目。正文当前按纯文本展示，不把编辑输入解释为 HTML，以避免脚本注入。未来若加入图片或富文本，需要另行设计上传、授权、格式过滤和预览。
