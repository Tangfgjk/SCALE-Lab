# 网站信息架构与体验要求

更新日期：2026-10-13。状态：内部讨论稿。沿用当前网站品牌并同步建设内容管理后台；研究方向、内容授权和首发页面范围仍待确认。

## 1. 页面要帮助访客完成什么

| 页面 | 访客任务 | 首发必要内容 | 不应出现的情况 |
| --- | --- | --- | --- |
| 首页 | 迅速判断团队研究什么，并进入相关内容 | 已确认名称、定位、研究方向入口、近期且已核验的动态、联系入口 | 未核验统计数字、未来成果写成已发表、占位相册 |
| 团队 | 找到负责人、研究人员及相关研究兴趣 | 经本人核准的姓名、身份、简介、公开照片／链接；无照片时使用统一文字卡 | 未授权照片、个人联系方式或校友去向 |
| 研究 | 从方向找到证据和成果 | 方向说明、可核验论文／项目、来源链接与明确的发表／项目状态 | 只有编号而无项目名称、无依据的指标 |
| 文化 | 判断团队工作方式及加入渠道 | 经确认的价值观、真实活动与时间、招生或联系说明 | 空白影像区和无法执行的“加入我们”入口 |

新闻详情与成果详情是否列入首发，需在 D03 已确定的网站与后台同步建设目标下进一步排期；若列表项没有详情页，至少给出稳定的可信外部来源。页面路径可以延续现有 `.html`，生产路由在技术选型确定后再统一。

## 2. 体验规则

- 导航：四个主入口名称统一，当前页清晰可见。手机菜单展开后文字与背景保持可读，关闭和键盘操作可用。
- 首页：主标题与说明让首次访客理解方向；两个主要行动入口分别指向研究与团队，按钮文字在浅色和深色背景均可读。
- 内容卡片：无照片或链接时显示经过设计的缺省状态，不输出 `@@@`、无效链接或空按钮。
- 研究 Demo：明确写“模拟数据”，三个选项切换时数值、圆环与解释同时更新；数值必须可见。真实课堂数据不进入公开站。
- 双语：中文版优先完成，英文版可并行开发。英文页面只有在导航、正文、图片说明、元数据和联系信息逐页审核后才公开；缺译文时该页面继续提供中文内容，不展示中英混杂的半成品。
- 可访问性：正文语义结构、可见焦点、图片替代文本、键盘操作和足够的文字对比度均需人工检查。不得只凭单一 Lighthouse 分数宣布合格。

## 3. 视觉基线与待定项

原前端设计稿指定深海军蓝与高饱和蓝；现有代码的主体是浅色主题，且有后加的颜色覆盖。建议先以当前浅色主题做一次完整视觉校准，再由实验室确认是否恢复深色方案。确定后只保留一套明确的颜色变量与组件状态，不再叠加主题覆盖补丁。

Logo 与人物照片的展示前提是来源及使用权清楚；若没有真实现场图，首页可暂不设画廊。图片数量由实际获授权素材决定，不为满足版式而使用虚构影像。

## 4. 首发体验验收建议

验收场景应由实验室成员和至少一位不熟悉项目的人各执行一次：

1. 从首页在 30 秒内说出实验室研究的主要方向，并找到一项可核验成果。
2. 找到负责人、拟研究方向和有效的申请／联系路径。
3. 在 390px 手机宽度及桌面宽度下完成导航、阅读与 Demo 切换；检查 200% 文字缩放后无内容遮挡。
4. 用键盘访问全部主要链接和 Demo 控件，确认焦点可见。
5. 每个准备公开的英文页面逐页检查标题、正文、说明与页面语言标记的一致性；英文版进度不阻断已合格的中文版。

性能指标可在确认部署平台和图片方案后制定；原设计稿中的 LCP、CLS 与 Lighthouse 目标保留为候选指标，不将未经测量的目标当成已达成事实。
