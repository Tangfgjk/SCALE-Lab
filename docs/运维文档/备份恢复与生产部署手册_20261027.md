# 备份恢复与生产部署手册

更新日期：2026-11-20。应用版本 V1.0.0，开发分支 V6-20261120。部署目标为 10.222.10.245:8089，申请域名 scalelab.ccnu.edu.cn。域名和学校 HTTPS 尚待开通，真实公网访问与云端恢复须单独验收。

## 1. 当前目录和资料位置

- 后端 `backend/`，入口 `backend/platform.js`，HTTP app 为 `backend/app.js`。
- 公开站 `frontend/public/`，后台 `frontend/admin/`，浏览器共用代码 `frontend/shared/`。
- 本地上传图片 `backend/storage/media`；设置 `MEDIA_ROOT` 可更换位置。
- 真实数据库仍为 `scale-lab-postgres` 容器中的 `scale_lab`，主机端口 5433。原 Docker 数据卷没有移动或替换。
- 本次备份 `backend/storage/backups/pre-engineering-20261027`。该目录有完整数据库、自有媒体文件和校验清单，含认证及个人资料，不能上传 GitHub。请另外复制到受控备份介质，单机副本不具备异机灾备能力。

## 2. 本地成套备份

`backend/scripts/backup-restore.js` 支持原生 PostgreSQL 客户端，或通过 `--container` 使用现有数据库容器的同版本客户端。

备份前停止本站服务及连接该数据库的其他客户端；工具发现其他客户端连接会拒绝备份。不要停止数据库容器。

```powershell
# 从项目根目录执行，连接信息按本地实际设置
$env:DATABASE_URL='postgres://用户名:密码@127.0.0.1:5433/scale_lab'
node backend/scripts/backup-restore.js backup --container scale-lab-postgres --directory backend/storage/backups/新的唯一目录名
npm start
```

备份目录必须不存在。成功结果包含 `database.dump`、`media/` 和最后生成的 `manifest.json`；没有有效清单的目录不算完成备份。清单包含来源数据库名、Git 提交、逐表数量及内容摘要、数据库备份与逐文件 SHA-256。失败必须查看错误并重新生成新的备份目录。

## 3. 隔离恢复与校验

先创建空数据库，设置新的空媒体目录。格式 2 备份记录 PostgreSQL 集群标识，允许跨集群恢复到同名数据库；旧格式或无法证明集群不同的同名目标仍被拒绝。工具拒绝覆盖来源数据库、已有 public 表或非空媒体目录。不会自动清空任何数据库。

```powershell
docker exec scale-lab-postgres createdb -U scale_lab scale_lab_restore_demo
$env:DATABASE_URL='postgres://用户名:密码@127.0.0.1:5433/scale_lab_restore_demo'
$env:MEDIA_ROOT='C:\安全位置\空的恢复媒体目录'
node backend/scripts/backup-restore.js restore --container scale-lab-postgres --directory backend/storage/backups/备份目录名
node backend/scripts/backup-restore.js verify --directory backend/storage/backups/备份目录名
```

`verify` 比对当前连接的目标库与 MEDIA_ROOT，不是只检查备份文件。备份时已确认的 27 张表和 109 个媒体文件在本轮隔离恢复中全部一致。测试恢复后切回正确的环境变量再启动日常网站，避免误连恢复副本。

数据库迁移采用前向兼容方式。应用版本回退使用代码基线与兼容数据库；需要整体恢复时恢复到独立环境再切换，不在生产库执行破坏性回滚。

## 4. 隔离测试与 CI

根目录 `npm run check` 检查正式源码语法。`npm test` 只接受全新、名称以 `_test` 结尾的数据库，自动创建随机测试管理员、独立媒体目录及 4104 测试服务。若测试库已有表，会直接停止，而不是删除资料。下一次复跑应另建空测试库。

GitHub Actions 文件 `.github/workflows/ci.yml` 使用临时 PostgreSQL，执行安装、编辑器构建、官方依赖审计、语法检查、重复迁移、15 组接口测试、生产 Docker 构建和独立容器验收。没有部署服务器凭据，不会连接本地真实数据库，也不会自动更新 gh-pages。

## 5. Linux 服务器首次部署

代码放在 /opt/scale-lab，私有环境配置放在 /etc/scale-lab/production.env，备份放在 /srv/scale-lab-backups，传输包放在 /srv/scale-lab-transfer。环境文件和备份目录仅限维护人员读取，不放入 Git 或公开站点目录。

正式访问链路：学校 HTTPS 网关 → 10.222.10.245:8089 → Caddy HTTP 8080 → 应用 3004。数据库不映射主机端口。当前 Compose 仅发布 8089，不占用 80/443；学校接入完成后，确认网关准确 IP/CIDR，填写 UPSTREAM_PROXY_CIDRS。不要信任全部内网或任何地址。EDGE_IP_RANGE 为应用临时容器的动态分配范围，PROXY_IP 必须在同一 EDGE_SUBNET 中且位于动态范围外，避免应用先启动占用代理地址；隔离恢复时同步修改三个地址配置。参考 Caddy 官方转发头与可信代理说明：https://caddyserver.com/docs/caddyfile/directives/reverse_proxy#headers

域名未开通时可检查 http://10.222.10.245:8089/ 的公开内容；生产 /admin/ 与 /api/admin/v1 会返回 HTTPS_REQUIRED，避免用明文入口发送管理密码。公网后台须通过学校 HTTPS 验收后使用，不修改为不安全 Cookie 来绕过此要求。

服务器联网时安装 Docker Engine/Compose 并拉取 V6-20261120。服务器无法访问 GitHub/镜像站时，在联网电脑生成该分支的 Git bundle 与生产镜像包，传输后校验 SHA-256；服务器仍保留 GitHub origin，通过本地 bundle 导入相同分支提交。依赖采用镜像内锁定安装结果，不传 Windows node_modules。

离线 Docker 安装脚本 infrastructure/install-docker-offline.sh 仅用于尚未安装 Docker 的 x86_64 Linux。它使用 Docker 官方静态 28.3.2 和官方 Compose v2.39.4 安装包，验证 Compose 校验和，不替换已有 Docker；维护人员需后续自行更新该静态安装版本。安装来源：https://docs.docker.com/engine/install/binaries/

环境文件以 infrastructure/.env.example 为模板，填写独立强数据库密码及匹配的 DATABASE_URL。ADMIN_PASSWORD、AUDIT_PASSWORD 在维护终端安全设置，不提交 Git。数据库内部地址是 db:5432，本地源库 127.0.0.1:5433 不可照搬。

首次恢复本地成套备份时，不先执行迁移或启动 app，以免目标库非空。备份须包含 database.dump、media/、manifest.json；保持本地源数据库与媒体文件不变。

```bash
export COMPOSE_ENV_FILE=/etc/scale-lab/production.env
export COMPOSE_PROJECT_NAME=scale-lab
export RESTORE_EMPTY_TARGET=yes
bash infrastructure/restore-local.sh /srv/scale-lab-transfer/paired-backup
docker compose --env-file "$COMPOSE_ENV_FILE" -f infrastructure/compose.production.yml run --rm --no-deps app node backend/db/migrate.js
# 在当前终端安全设置并 export ADMIN_PASSWORD、AUDIT_PASSWORD 后：
docker compose --env-file "$COMPOSE_ENV_FILE" -f infrastructure/compose.production.yml run --rm --no-deps -e ADMIN_PASSWORD -e AUDIT_PASSWORD app node backend/scripts/provision-production-accounts.js --apply
docker compose --env-file "$COMPOSE_ENV_FILE" -f infrastructure/compose.production.yml up -d --no-build --pull never app proxy
```

restore-local.sh 先验证备份和空目标，再通过 PostgreSQL 17 容器执行事务恢复，核对逐表内容与文件校验和，并修复应用媒体卷所有权。恢复后修改账号会正常改变认证和审计表，不应再用修改前的备份清单要求这些表完全一致。

provision-production-accounts.js 仅在生产环境且带 --apply 时工作：更换 admin 密码、创建或更新 scale_audit 内容维护账号，并撤销两者旧会话。不会改本地源库账号；再次执行会再次轮换密码。密码需 12–128 字符，生产启动仍拒绝已知演示密码。不要将申请表里的六位旧密码用于服务器；向审核方补充实际正式凭据。

若使用全空站点而不是导入现有内容，才先运行 db/migrate.js 和 bootstrap-admin.js。不要重放历史导入脚本覆盖人工内容。

## 6. 生产备份与恢复工具

提供 `infrastructure/backup.sh` / `restore.sh`，在 Linux 部署主机使用。这套工具使用 media.tar、SHA256SUMS、COMPLETE 格式，不能直接读取本地 Node 工具的 manifest.json 格式；首次 Windows 到服务器迁移使用第 5 节 restore-local.sh。指定受控的绝对路径环境文件，不把备份写入网站或仓库公开目录。

```bash
export COMPOSE_ENV_FILE=/srv/scale-lab/infrastructure/.env.production
bash infrastructure/backup.sh /srv/scale-lab-backups/一个新的时间目录
```

备份会暂停应用、通过数据库容器导出数据库、通过应用镜像打包媒体、生成 SHA256SUMS/应用提交/完成标记，退出时恢复应用。定时任务应检查退出码、备份生成时间、磁盘空间与远端复制结果；具体频率、保留时间及告警渠道在云环境确定后设置。

恢复工具要求显式指定全新的 Compose 项目、空数据库、空媒体卷。恢复可先在另一台测试主机演练；同机并行恢复还需在独立环境文件设置不同的 EDGE_SUBNET/PROXY_IP，避免网络冲突。不启动代理或占用正式 80/443。

```bash
export COMPOSE_ENV_FILE=/srv/scale-lab/infrastructure/.env.restore
export COMPOSE_PROJECT_NAME=scale-lab-restore-check
export RESTORE_EMPTY_TARGET=yes
bash infrastructure/restore.sh /srv/scale-lab-backups/已完成的备份目录
```

脚本拒绝已有 public 表或非空媒体卷，校验备份文件并检查媒体归档路径；恢复后还要核验内容和图片、应用迁移，并处理演示口令，再考虑切换正式服务。Linux 生产备份脚本本轮仅作语法检查；本地数据恢复使用 Node 工具进行了实际演练，不能将两者混称为云端恢复已通过。
