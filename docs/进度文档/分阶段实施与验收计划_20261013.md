# 分阶段实施与验收计划

更新日期：2026-10-13。状态：建议计划。已确认网站与内容管理后台同步建设、本地开发后部署云服务器、中文版优先、后台人员可编辑发布。具体时间随云服务选型与内容核验进度确定，不预设人员工期。

具体任务状态与验收证据统一在[后端与前后端联调进度跟踪](后端与前后端联调进度跟踪_20261013.md)维护；技术实施细节见[后端与前后端联调具体实现方案](../设计文档/后端与前后端联调具体实现方案_20261013.md)。

## 当前基线与下一步

公开站的学术编辑式优化副本已获认可，后续实现以 `frontend/visual-preview-20261013` 为基线，开发时继续微调；后台采用 A「侧栏工作台」。目前这两部分仍是静态页面。前台从 `frontend/assets/js/data.js` 读取内容，Express 公开 API 从 `frontend/server/data/content.json` 读取另一份，管理 API 尚未实现。下一阶段的首要目标是让**一条经核验的内容从后台草稿进入 PostgreSQL，经发布后出现在公开 API 和优化版页面，撤回后同步消失**。

| 顺序 | 本轮交付 | 可验收的结果 |
| --- | --- | --- |
| 1 | 核对现有两份内容数据，标出重复、冲突、占位和来源；确定首条演示内容 | 形成逐条待核验清单；演示数据与可公开内容明确分开 |
| 2 | 建立 PostgreSQL 本地连接、版本化迁移和开发种子；先落身份、内容、修订、发布、来源、审计的核心表 | 空库可重复迁移；草稿和已发布修订能并存 |
| 3 | 把 A 原型转为受登录保护的后台外壳，先完成新闻的列表、编辑、预览、发布、撤回、记录 | 指定人员可独立走通新闻全流程；未登录不能访问写接口 |
| 4 | 公开 API 改从 PostgreSQL 读取已发布新闻；优化版首页接入该接口并呈现空状态／错误状态 | 发布后首页更新，草稿不出现，撤回后首页与 API 同时消失 |
| 5 | 沿同一发布机制逐模块扩展研究方向、论文、项目、成员、活动相册、媒体库与站点设置 | 每类采用专用字段和操作界面；图片授权、来源及双语检查逐项验收 |

选择新闻作为第一条纵向开发路径，是因为它能验证完整发布流程和前台展示，同时字段与授权关系相对简单；并不改变首版全部模块纳入范围。中文流程优先，英文结构同步预留。首个里程碑完成后，再将 `data.js` 和 `content.json` 中对应的新闻数据依赖移除，避免继续维护两份内容。

## 阶段 0：确认对外口径与发布目标

**输入**：项目目标与待确认决策中的 D01–D12；D01、D03、D07–D12 已获得用户答复。

**工作**：沿用当前网站名称与 Logo；统一页面标题和数据口径；确认研究方向、内容负责人、授权范围、云服务商、域名与运维责任。中文版优先，英文版可并行开发；后台人员同时具备编辑和发布能力。

**完成标准**：D02、D04–D06 有可记录的决定；D08 中云服务具体选型、域名与运维责任明确；首发范围得到负责人认可。

## 阶段 1：网站修复与后台基础并行

**网站线**：修复导航、按钮和 Demo 对比度；整理页面所有 `@@@`、无效链接与状态疑点；没有获准照片时使用文字版布局。

**后台线**：确定同一内容模型，本地使用 PostgreSQL 建立可迁移的数据结构；设计兼容专用账号与学校统一身份认证的登录接口，以及不超过 5 人的内容管理人员和管理员账号。根据教师主页建立初始来源清单，但不把公开页面当作照片再展示授权。

**完成标准**：四页在桌面和 390px 手机宽度均可阅读、导航；Demo 数值可见且选项可用；首批内容均标注来源和“已核验／暂不展示”；后台模型与权限方案可评审。

## 阶段 2：内容后台最小可用版与公开页面集成

**网站线**：补齐经核验的论文来源、项目名称、成员资料和新闻链接；实现空内容隐藏、详情与联系路径。中文版优先验收，英文版可同步开发，逐页完成翻译审核后再公开。

**后台线**：将成员、新闻、论文、项目、研究方向、活动相册、媒体库和站点设置全部纳入首版。实现登录、编辑、草稿、预览、发布前检查、发布、图片与授权记录、修订历史和撤回；所有获准人员均可编辑并兼任发布。将前端及公开 API 的重复数据合并为一份持久化内容源，只输出已发布且允许公开的字段。

**完成标准**：指定人员可在后台管理首版全部范围并发布内容和站点设置，发布后页面与 API 一致变化；操作有记录；草稿不出现在公开结果；撤回后公开内容下线；已发布论文和项目有可核验的来源。

## 阶段 3：网站与后台联合验收、公开发布准备

**工作**：按网站信息架构文档进行陌生访客任务测试、键盘及移动端检查、链接检查；由指定人员走通“创建草稿→预览→发布→修改→撤回”全流程；实验室负责人逐页确认事实、授权和文字。准备云服务器的部署、域名、备份、监控及下线联系人，并进行本地到云端的迁移验证。

**完成标准**：关键访客任务可完成；后台完整发布流程可用；事实与授权检查通过；无阻断级问题；发布人与回退／下线办法明确。具体性能阈值在部署环境确定后设定并实测。

## 阶段 4：持续运营与后续能力

**工作**：在已上线的后台基础上，完善批量导入、DOI 辅助录入、统计报表及定期复核；按实际使用反馈优化权限和编辑体验。

**完成标准**：成员变动、成果新增、授权撤回和定期复核均有指定责任人；后台变更与授权处理可追溯。

## 工作分配建议

| 角色 | 主要责任 |
| --- | --- |
| 实验室负责人 | 确认方向、对外口径、成果真实性与内容责任人 |
| 内容管理人员 | 收集来源、整理内容、检查授权与语言、预览并发布；可由同一人完成编辑和发布 |
| 管理员 | 具备内容管理权限，并负责后台账号和站点设置 |
| 技术负责人 | 修复体验问题、统一内容源、实现发布过滤及云端部署 |

内容管理人员可以自行完成编辑与发布；系统仍需记录发布前检查结果、操作账号与时间，以便追溯。
