## 4. 接口与前端

- 成员列表与详情最多两次数据库查询（无头像时一次），详情按 slug 定位，继续执行简介/邮箱/去向/照片的字段授权与媒体有效性检查。
- 新闻/活动列表支持 page、pageSize（1–100）、q、year，返回 total/pages/years；默认每页 10 条，详情仍返回全文。
- 首页新闻请求只取 3 条；首页活动只请求最新 3 条封面概览。文化页保留全部相册图片与完整图文入口，批量查询有效媒体，不再返回完整富文本正文。
- 新闻页搜索、年份和翻页使用服务端筛选，切换语言重置页码；公开 URL 不变。
- Pages 导出遍历所有分页并核对总数；静态运行时使用同一快照完成搜索、年份筛选和分页。新快照只在本地验收，没有自动改写此前分享的 gh-pages。
- 实际公开内容导出：6 篇新闻、2 个活动、49 名成员、51 张公开图片；动态站和静态预览的搜索与详情均通过浏览器验证。
- 活动摘要本来已经动态支持 1000 字，本轮统一前后端规则，并增加 500/501、1000/1001 和类别切换边界验证，不静默截断。

## 5. 测试与 CI

- 写入型冒烟测试要求 NODE_ENV=test、明确的 TEST_BASE_URL（禁止3004）、以 `_test` 结尾的数据库与独立 MEDIA_ROOT。
- `test-isolated.js` 拒绝非空测试库，在空库执行全部 12 个迁移两遍，生成随机测试账号并启动 4104 服务，结束后关闭测试服务，不重用本地 admin。
- 数据库迁移校验统一 LF 换行，并兼容历史 Windows CRLF 校验记录；额外测试确认 CRLF 差异可兼容、无效校验记录仍拒绝执行，避免恢复到 Linux 时误判 SQL 被修改。
- 15 组测试通过：新闻发布/修订/双语/媒体/活动，成员/头像/双语/详情，研究/双语，设置，账号，内容列表，公开接口分页/查询数/安全配置契约。
- 后端与编辑器修复依赖后完整回归再次通过；之后补充的摘要和 overview 边界用最终一轮回归验证。
- `.github/workflows/ci.yml` 在 V5 push/PR 上执行构建、依赖审计、源码与 shell 语法检查、隔离测试、生产镜像构建和临时生产容器验证。远端 Actions 的实际状态以运行记录为准，配置存在不等于已运行通过。

## 6. 生产运行与安全

- Node 24 多阶段生产镜像实际构建成功，编辑器在构建时重新打包；应用使用非 root、只读根文件系统和独立媒体卷。
- 在完全独立的临时 PostgreSQL 和应用容器中验证：健康状态、强配置要求、Secure Cookie、CSP/HSTS、CSRF 拒绝、图片上传/授权/新闻发布、重启后文章与图片保留、重启后错误登录继续限流，全部通过。临时资源只按本轮生成名称清理，不影响现有容器。
- 可信代理按地址/CIDR 设置；不直接信任任意 X-Forwarded-Proto。生产启动拒绝缺少配置、弱数据库密码及已知演示账号密码；本地 admin/admin 没有自动更改。
- 生产 Compose 使用 PostgreSQL 内网、Caddy 80/443、数据库/媒体/证书持久化卷。Linux 成套备份恢复脚本已提供并通过语法检查，云端实际运行仍待部署。
- 初次生产构建遇 Docker Hub 连接失败，使用本机缓存的 Node 24 镜像及现有系统代理完成构建，未更改系统代理设置。

## 7. 依赖审计与编辑器

官方 npm 审计发现后端 body-parser/Multer 与管理端 markdown-it/Tiptap 问题。本轮升级后两端审计均为 0 个已知漏洞；这是本次审计时间点的结果，CI 持续复查。

Tiptap 漏洞没有 2.x 修复，升级到 3.32.0，适配 StarterKit 重复扩展、链接校验和 setContent 更新参数，保留既有 JSON schemaVersion 与图片节点格式。升级后混选图片、选中样式、禁用图片拖动、混选删除、撤销、全选、剪贴板和粘贴布局 8 项浏览器回归全部通过。

参考：[Tiptap 官方升级说明](https://tiptap.dev/docs/guides/upgrade-tiptap-v2)、[安全公告](https://github.com/advisories/GHSA-cp6q-959q-f8rh)。
