## 1. 目标、范围与验收边界

### 1.1 本轮目标

将目前仅能录入标题、摘要、纯文本正文且预览只是后台文本框的新闻编辑流程，升级为**可视化富文本编辑 + 媒体库统一管理 + 所见即所得实时预览 + 公开端一致渲染**的内容生产流程。同时抽象共享组件，让研究方向、项目简介、成员简介等模块后续按配置复用。保留 V2 的中文先发布、按语言独立审查、版本指针、审计日志及媒体公开授权规则。

本轮不把网站改为任意页面搭建器；字体、字号、排版布局均有主题化约束，避免新闻内容破坏网站统一视觉和移动端适配。

### 1.2 完成定义（DoD）

1. 非技术编辑人员能通过可见工具栏完成标题层级、粗斜体、链接、列表、引用、段落对齐、分割线及图片的内容编辑；常用功能支持快捷键；撤销、重做正常。
2. 图片必须先成为媒体库资产，并具备对应公开授权；编辑器内支持“上传到媒体库”和“选择已有图片”的统一入口。未授权资产不可公开展示或成功发布。
3. 新闻具备封面与图文穿插能力，允许调整插图宽度档位、左右/居中对齐、替代文本/图注；手机端不溢出、不产生不可阅读的浮动布局。
4. 编辑过程中无需先保存即可实时预览；桌面/手机宽度切换；同一渲染器用于预览和公开新闻详情页，内容、图片顺序、排版一致。
5. 草稿保存、核查、发布、撤回、已发布旧版本留存、版本冲突检测、中文英文隔离与授权撤回均通过回归测试；旧纯文本新闻能无损显示并重新编辑。
6. 其他工作台模块至少完成共享编辑器的接入接口/组件能力与示范接入，哪些字段启用富文本由模块配置控制，不改动结构化业务字段。
7. 更新运行说明、接口契约、数据库迁移记录、内容发布规范、测试及缺陷记录，给出新人的操作步骤。

### 1.3 非目标

- 不支持自由嵌入任意 HTML、JavaScript、iframe、外部脚本、任意 CSS，避免 XSS 与样式污染。
- 暂不做复杂表格、多栏杂志排版、页面级拖拽、视频上传和多人同步协作。
- 不更换现有 Express + PostgreSQL + 原生前端的整体架构；可以按实际维护成本引入经过评估的编辑器依赖。

### 3.1 组件边界与文件建议

```text
  rich-editor.css           # 编辑区样式

```

实现选型：优先评估 **TipTap（ProseMirror）** 或 **Editor.js** 等成熟组件；若采用 TipTap，须注意其现代构建工具需求与现有“原生 JS + Express 静态资源”的集成成本。V3 在进入开发前先完成一个兼容原技术栈的编辑器 PoC，明确 bundle、依赖许可证、版本锁定、浏览器兼容性。不要凭空假定某库已有所需功能。

### 3.2 文字功能

| 需求 ID | 编辑能力 | 交互方式 | 验收 |
| --- | --- | --- | --- |
| ED-01 | 段落、H2/H3（新闻主标题仍由标题字段统一生成） | 工具栏下拉、Markdown 风格输入可选 | 层级规范，不能任意插入 H1 |
| ED-02 | 粗体、斜体、删除线、行内代码（可选） | 按钮 + `Ctrl+B`/`Ctrl+I` 等快捷键 | 选中内容后即时生效；撤销有效 |
| ED-03 | 有序/无序列表、引用、分割线 | 工具栏、键盘 | 嵌套层级受限，手机正常换行 |
| ED-04 | 超链接 | 插入/编辑链接弹窗 | 只允许 `https:`/`http:`/经确认的安全站内路径，外链加安全属性 |
| ED-05 | 字号及字体效果 | 主题化“正文/小字/引言/强调”档位 | 不允许任意 CSS/px，保持网站一致 |
| ED-06 | 对齐和布局 | 左对齐、居中、受控图文块 | 无固定宽度，不允许横向溢出 |
| ED-07 | 撤销、重做、键盘操作 | 工具栏 + `Ctrl+Z` / `Ctrl+Shift+Z` | 输入、删除、图片操作均可撤销 |
| ED-08 | 自动保存状态提示（P1） | “未保存/保存中/已保存/冲突” | 不意外覆盖他人修订；明确失败提示 |

工具栏必须有文字提示、无障碍名称及键盘焦点；快捷键不可替代可见按钮，兼容 Windows `Ctrl` 和 macOS `Cmd`，不阻止输入法合成过程。

### 3.3 文档格式与版本兼容

使用**版本化结构化 JSON**存储富文本原始文档，不存未经清洗的任意 HTML；不要将 Markdown 字符串作为唯一真相来源。建议：

```json
{
  "schemaVersion": 1,
  "type": "doc",
  "blocks": [
    {"id":"b1","type":"paragraph","children":[{"type":"text","text":"实验室开展了学术交流。","marks":["bold"]}]},
    {"id":"b2","type":"image","assetId":"<媒体资产UUID>","caption":"活动现场","width":"medium","align":"center"}
  ]
}
```

该 JSON 是**建议接口契约示例**，可按照选型映射为 TipTap/ProseMirror 的原生 JSON，但必须最终冻结唯一版本格式；约束节点与 marks 白名单、树深、块数量、文本长度和 JSON 字节数。`assetId` 只允许数据库中的 UUID，不允许不受控的图片 URL。服务端校验是权威，前端校验仅提升体验。

存储建议：`content_localizations.extra_json.richText` 保存结构化正文及 schemaVersion，原有 `body` 字段保留**兼容性纯文本提取**；不要同时维护两个可独立修改的正文源。读取旧记录若没有 `richText`，按纯文本分段迁移到编辑器，渲染不得丢失换行。避免因首次打开旧稿而自动变更已发布版本。

## 4. P0 — 媒体库与新闻图片工作流

### 4.1 具体流程

编辑器点击“插入图片” → `media-picker` 展示已启用/已授权图片 → 选择已有资源，或进入“上传到媒体库” → 上传并补齐来源、署名、替代文本、版权及人物授权 → 激活资源 → 插入 `assetId` 节点 → 设置图注/宽度/对齐 → 保存草稿 → 核查与发布检查 → 公开页解析图片引用。

- 不允许把图片 base64、文件路径、未经授权的第三方 URL 直接保存进新闻正文。
- 编辑器里刚上传但还处于待核状态的图片可以在管理预览中作为**未授权占位**显示，不能被发布为公开图片。
- 选择已有图片时默认只显示可公开资源；可切换查看“待核资源”，但必须明显标注状态。
- 封面从媒体库选择；新闻详情支持封面、正文插图，首页卡片可配置封面缩略图，缺省时仍保持原样式。
- 图片被停用或撤回版权/人物授权后，公开 API 与文件接口必须立即阻止公开访问，前台显示受控占位而不是断裂布局；后台列出受影响新闻以便修复。

## 5. P0 — 新闻后台、数据库与 API 改造

### 5.1 数据库迁移

新增 `frontend/server/db/migrations/008_news_rich_content.sql`（序号须以实际 V3 合并时最新迁移为准，禁止覆盖已执行迁移），建议包含：

1. 对已有 `news_revisions.cover_asset_id` 增加到 `assets(id)` 的外键、查询索引（必要时处理历史脏值），复用已预留字段而不是重复加列。
2. 对新闻修订的封面及正文图片建立**修订级引用记录**。默认优先新增独立的 `news_revision_assets` 表，避免把新闻正文位置语义和活动相册的排序语义混入已有 `content_assets`；只有在完成字段兼容性、唯一约束和相册回归评估后，才考虑将两者抽象为共享表。引用记录至少包含 `revision_id`、`asset_id`、`purpose`（`cover`/`body`）、`block_id` 或稳定顺序、图注和展示参数，并保留历史修订引用。
3. 富文本 JSON 优先使用已有 `content_localizations.extra_json`；若后续需要索引、全文检索或 JSON 大小控制，再评估独立列，不为同一内容建立重复数据源。
4. 迁移应有 `NOT NULL`、外键、唯一性及索引约束，并保持旧数据可读；执行迁移两次应幂等或由现有迁移记录阻止重复执行。
5. 审计日志记录媒体引用变更及实际发布版本；不得把未发布草稿引用错误算作公开使用。

```json
}
```

`expectedVersion` 用于更新/核查/发布的乐观并发控制，新建时按现有规则无需传入；`richText.blocks` 示例省略，正式正文必须非空。错误码建议：`INVALID_RICH_DOCUMENT`(400)、`ASSET_NOT_FOUND`(404)、`ASSET_NOT_CLEARED`(409)、`VERSION_CONFLICT`(409)、`NOT_CHECKED`(409)。统一现有 `{data,meta,requestId}` 输出 envelope。

### 5.3 发布一致性与并发

- 前端动态预览不改变审查状态；**只有保存产生的确定修订版本**可被核查与发布。
- 核查与发布应绑定 `revisionId`/`expectedVersion`，同时校验图片。若资源撤权，应提示具体素材并阻止新发布。
- 修改已发布新闻生成新草稿，但公开页仍展示旧修订；新版发布成功后原子切换 `content_publications` 指针。
- 中英文分别存储结构化正文；中文更新共享事实导致英文旧版失效的 V2 规则继续执行。中文引用的图像不自动成为英文版本已授权的译文或图注。
- 媒体授权撤回后，公开读取端每次按现有授权规则过滤/阻止图片，不能仅在发布当时校验；CDN 部署时需配置适当缓存失效策略。

## 6. P0 — 实时预览与统一渲染

### 6.1 共享渲染

- `rich-renderer.js` 仅从白名单结构化节点生成 DOM（使用 `textContent`/安全属性设置），严禁直接插入用户 HTML；链接协议和图片源严格受控。
- 后台编辑器右侧/下方与公开 `news.html?slug=...` 详情页使用相同 `rich-renderer.js`、`rich-renderer.css`；页眉页脚等外围站点框架不同，但**正文版式一致**。
- 编辑时按节流渲染内存中的未保存文档；保存后的 API 预览仍作为正式核对入口。实时预览显著标识“未保存/未审核内容”。
- 窄屏切换为“编辑/预览”标签，宽屏双栏；提供 390px 和桌面预览宽度档位，避免固定像素布局。
- 图片加载失败时显示占位及图注；状态变更后后台/前台可及时反映。考虑 `prefers-reduced-motion` 与可访问性。

### 6.2 文件改动

- `frontend/admin/index.html`：将新闻正文 `<textarea>` 替换为可视化编辑器挂载点、工具栏、媒体选择器、实时预览面板；保留原标题、摘要、日期、语言与来源等结构化字段。
- `frontend/admin/app.js`：编辑器状态、保存/恢复、版本冲突、预览同步、媒体选择与原新闻 CRUD 衔接；移除手写的简陋 HTML 预览。
- `frontend/visual-preview-20261013/news.html`、相应 `assets/js/*`：详情页解析 `richText`，纯文本新闻兼容渲染；首页新闻列表显示封面（可选）。
- `frontend/visual-preview-20261013/assets/css/news.css`：新闻详情版式仅引用统一样式，不出现两套不一致的富文本规则。

## 7. P1 — 工作台其他板块复用

**先做可配置共享组件，不应全量一键替换每个 textarea。**推荐提供 `RichEditor({value, schema, toolbarPreset, allowImages, allowLinks, maxLength, readOnly, onChange, onAssetInsert})`，并对数据模型各自维护适配器。

| 模块 | 建议复用方式 | 注意事项 |
| --- | --- | --- |
| 新闻 | Full（全部本轮功能、图片、封面、实时预览） | P0 首先完整落地 |
| 研究方向 | Standard（段落、标题、列表、链接、选配图片） | 仅在研究方向简介获得正式批准后发布内容 |
| 项目介绍 | Standard（结构化说明 + 图文） | 项目编号、资助单位、时间、状态仍为单独字段 |
| 论文 | Basic（摘要与说明格式） | 作者、DOI、期刊、年份等保持结构化，不强行做富文本 |
| 成员简介 | Basic（粗体/链接/列表，是否允许图片需独立审核） | 个人隐私与字段授权规则不因编辑器复用而放宽 |
| 活动相册 | 沿用专用图片上传/排序控件，仅图注可共享轻量格式工具 | 不取代照片授权、封面和排序模型 |
| 站点设置 | 通常仅简单文字与链接 | 不应开放随意改变首页排版的富文本入口 |

建议 V3 完成新闻 Full + 研究方向或项目的 **1 个 Standard 示范模块**，其余模块完成可复用接入清单及测试设计。若日程允许，再逐一上线。

## 8. P1 — 内容管理与公开端易用性完善

### 8.1 列表分页和搜索

- 后台新闻、媒体、成员、研究及操作日志目前多处仅返回最多 100 条。实现服务端 `page/pageSize/q/status/locale/sort`（按模块适配），校验 `pageSize` 上限，返回真实 `meta.total`，使用稳定排序与索引；前端增加分页控件和筛选状态。
- 内容选择弹窗必须使用服务端分页，避免资产超过 100 张后无法选到旧图片。
- 分页后的媒体使用查询仍要反映引用关系和有效公开状态。

### 8.2 错误与状态提示

- 明确区分“内容尚未保存”“正在保存”“保存失败”“核查未通过”“媒体不可公开”“版本冲突”和“公开发布成功”。
- 在点击发布前列出当前修订的媒体清单及授权警示；不可直接静默跳过未授权图片。
- 空白文章/超大 JSON/重复媒体/非法链接/不支持图像类型有确定错误提示，不能出现无响应按钮。
