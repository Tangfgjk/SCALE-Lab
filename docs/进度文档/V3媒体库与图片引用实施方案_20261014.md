# V3 媒体库与图片引用实施方案

更新日期：2026-10-15  
适用分支：`V3-20261015`  
状态：核心功能已实施，正在进行验收与后续补强

## 当前实施进度（2026-10-14）

已完成媒体库、文件夹、资产归档、共享媒体选择器、新闻封面与正文图片引用、活动相册复用、授权发布门禁及公开端安全降级。数据库迁移 `008_media_library_folders.sql`、`009_news_media.sql` 已在本地数据库应用，新闻和媒体/活动相册冒烟测试通过。

仍需后续补强：移动端视觉回归、第二个业务模块接入、真实浏览器图片发布 E2E，以及首页新闻卡片是否展示封面缩略图的产品决定。

## 1. 目标

在现有媒体资源页面基础上，建立统一的图片资产管理和引用机制：

1. 图片先进入媒体库，完成来源、替代文本、署名及公开授权记录。
2. 新闻编辑器可以从媒体库选择封面图和正文插图。
3. 活动相册可以从同一媒体库选择图片，但继续独立管理活动信息、封面、顺序和图注。
4. 移动图片、修改展示名称或整理文件夹不会破坏新闻、相册、成员头像等已有引用。
5. 停用或撤回授权后，公开页面立即停止输出图片，并显示可控的降级状态。

## 2. 页面职责

### 媒体资源

负责图片资产本身：上传、预览、展示名称、文件夹、搜索、筛选、来源、替代文本、署名、授权、启用、停用、引用查询和归档。

### 新闻动态

负责新闻内容：标题、摘要、富文本正文、封面、图片位置、图注、宽度、对齐、修订、核查和发布。图片通过媒体选择器引用，不直接上传到正文。

### 活动相册

负责活动内容：活动标题、日期、简介、封面、图片顺序和逐图说明。图片通过媒体选择器引用，不把相册当作媒体文件夹。

### 共享能力

新闻、活动相册、成员资料共用媒体选择器、图片预览卡片、授权状态提示和引用查询；各模块保存自己的业务排序与展示参数。

## 3. 核心数据规则

### 3.1 稳定资产身份

- 每个资产使用不可变 UUID `assetId`。
- 文件夹路径、展示名称和内部 `storage_key` 不作为业务引用。
- 移动或重命名只更新媒体元数据，不更新新闻或相册正文。

### 3.2 文件夹模型

新增逻辑库和树形文件夹：

- `media_libraries`：媒体库，如“新闻图片”“活动图片”“成员照片”。
- `media_folders`：`library_id`、`parent_id`、`name`、排序和状态。
- `assets`：增加 `display_name`、`folder_id`；保留现有 UUID、文件键、尺寸、授权和状态。

第一阶段每个资产只归属一个文件夹；标签和跨库收藏以后再扩展，避免第一版移动规则过于复杂。

### 3.3 引用模型

新增新闻修订级引用表 `news_revision_assets`，至少包含：

- `revision_id`
- `asset_id`
- `purpose`：`cover` 或 `body`
- `block_id` 或稳定顺序
- `caption_zh`、`caption_en`
- `width`：`small`、`medium`、`large`
- `align`：`left`、`center`、`right`

活动相册继续使用现有 `content_assets` 保存相册修订的图片顺序和图注。成员头像和站点 Logo 继续使用各自的结构化外键。

### 3.4 移动、替换和删除

- 移动文件夹：允许，所有引用保持有效。
- 修改展示名称：允许，所有引用保持有效。
- 停用资产：允许，公开接口立即阻止文件输出，并列出受影响内容。
- 撤回授权：允许，发布接口和公开接口都必须重新检查授权。
- 替换图片内容：默认生成新资产或新版本，不覆盖已发布修订正在使用的文件。
- 删除：不做硬删除；有引用的资产只能停用或归档。

## 4. 实施顺序

### 阶段 A：媒体库基础升级

1. 新增库和树形文件夹迁移。
2. 媒体列表增加缩略图、展示名称、文件夹、授权状态、引用数量。
3. 增加新建文件夹、重命名、移动、搜索和筛选。
4. 增加资产详情和引用位置查看。
5. 保持现有上传、授权、启用和停用流程兼容。

### 阶段 B：共享媒体选择器

1. 提取共享 `media-picker` 组件。
2. 默认只显示已启用且授权完整的图片。
3. 支持按库、文件夹、名称和授权状态筛选。
4. 允许从新闻或相册页面跳转到媒体资源上传；上传完成后返回选择器。
5. 待核图片只在后台明确标注后可预览，不允许进入公开发布结果。

### 阶段 C：新闻图片引用

1. `news_revisions.cover_asset_id` 增加正式外键和索引。
2. 新增 `news_revision_assets` 迁移。
3. TipTap 增加媒体图片节点，保存 `assetId`、图注、宽度和对齐方式。
4. 新闻编辑器增加封面选择和正文插图工具。
5. 保存草稿时事务性写入正文 JSON、封面引用和正文引用。
6. 核查与发布时校验所有引用资产的启用状态和授权状态。
7. 公开详情页按已发布修订解析图片，不泄露草稿引用。

### 阶段 D：活动相册复用

1. 将活动相册现有图片选择改为共享媒体选择器。
2. 保留相册自己的封面、排序和图注编辑。
3. 验证移动媒体文件夹不会改变相册顺序。
4. 验证停用或撤权图片后相册公开页安全降级。

### 阶段 E：验证和文档

1. 数据库迁移可重复执行，旧媒体和旧相册数据不丢失。
2. 增加媒体移动、重命名、引用、停用、撤权和替换测试。
3. 增加新闻封面、正文图片、相册引用的端到端测试。
4. 完成桌面和手机页面检查。
5. 更新 README、接口文档、进度文档和问题记录。

## 5. 主要接口计划

| 方法 | 接口 | 用途 |
| --- | --- | --- |
| GET | `/api/admin/v1/media/libraries` | 获取媒体库和文件夹树 |
| POST | `/api/admin/v1/media/folders` | 新建文件夹 |
| PATCH | `/api/admin/v1/media/folders/:id` | 重命名或移动文件夹 |
| PATCH | `/api/admin/v1/assets/:id` | 修改展示名称、文件夹和元数据 |
| GET | `/api/admin/v1/assets` | 按库、文件夹、授权和状态查询资产 |
| GET | `/api/admin/v1/assets/:id/usages` | 查看成员、新闻、相册等引用 |
| GET | `/api/admin/v1/news/:id/assets` | 查看新闻修订图片引用 |
| PUT | `/api/admin/v1/news/:id/draft` | 保存新闻正文与图片引用 |
| GET | `/api/v1/assets/:id/file` | 仅输出允许公开的图片 |

接口命名会优先兼容现有 `/api/admin/v1/assets` 路由，避免无必要地破坏当前媒体库页面。

## 6. 验收标准

- 图片上传、授权和启用流程保持可用。
- 新闻可以选择封面和正文图片，并实时预览。
- 活动相册可以选择同一媒体库中的图片并设置自己的顺序。
- 移动或重命名图片后，新闻、相册和成员头像引用仍然有效。
- 已发布内容引用的图片被停用或撤权后，公开图片请求立即失效。
- 有引用的图片不能被硬删除，后台可以查询受影响内容。
- 历史新闻修订仍保留原来的图片引用。
- 旧的纯文本新闻和旧的活动相册无需手工重做即可继续显示。

## 7. 第一阶段默认决策

以下规则建议作为实现默认值，如需改变应在编码前确认：

1. 一个资产第一阶段只放在一个文件夹中。
2. 新闻和相册共用媒体库资产，但不共用业务引用表。
3. 移动和重命名不影响引用。
4. 替换文件生成新资产，不覆盖历史发布文件。
5. 有引用的资产不允许硬删除，只能停用或归档。
6. 公开接口每次读取都检查资产状态和授权，不依赖发布时的一次性检查。
